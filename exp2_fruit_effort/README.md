# 实验2（图片—词 + 自由反应 + 漂移效能）PsychoPy 程序说明

对应《实验内容》2.1–2.3：288 个区段（interval）、每段一个固定作答窗口（2/3/4 s）、
被试在窗口内自主决定做多少题、图片—词干扰判断、连续计分、分数 yoking、
每 2–4 区段一次主观探针。

全部代码在 **`exp2_fruit_effort.py`** 一个文件里，用 PsychoPy 的 **Coder** 打开运行。
水果刺激图第一次运行会自动生成到 `stimuli/`（不需要你准备素材）。

---

## 1. 相对实验1 改了什么

| 维度 | 实验1 | 实验2 |
|---|---|---|
| 时间单位 | 一个**试次** = 注视点+Cue+目标+两段反馈 | 一个**区段** = 注视点 + 自由作答窗口 + 一段反馈 |
| 反应时限 | 个体化时限（≈796 ms），超时不算 | **没有单题时限**，只受区段窗口约束 |
| 单区段题量 | 固定 1 题 | **被试自己决定**（能做几题做几题） |
| 任务 | Stroop 词（判断墨色） | 图片—词干扰（判断**图片**、忽略文字） |
| 反馈 | 奖赏 + 效能，两条 1000 ms | 一条 1500 ms：本次得分 + 分数是否取决于表现 |
| 计分 | 二元 $0.50 / $0.00 | **连续**：每答对 +10 分 |
| yoking | 从 10 个表现试次里抽 0/1 | 从 10 个表现**区段的得分**里抽一个值 |
| 漂移单位 | 288 个试次 | 288 个区段（换种子，与实验1可比但不同） |

实验2 的目的（2.1）是把“反应快慢”和“反应谨慎度”分开：没有硬时限，才能用 DDM
同时估计漂移率与阈限。

## 2. 环境准备

1. PsychoPy Standalone（2023.2 LTS 或 2024.x）：<https://www.psychopy.org/download.html>
2. **必须用 PsychoPy 自带的 python**（它带 Pillow，首次运行要用它画水果图）：
   - 图形界面：PsychoPy → Coder → 打开本文件 → 绿色 ▶ Run
   - 命令行：`"C:\Program Files\PsychoPy\python.exe" exp2_fruit_effort.py`
3. 中文字体默认 `Microsoft YaHei`（macOS 改 `CFG["FONT"] = "PingFang SC"`）。
4. 键盘：D F J K 对应 苹果 / 梨 / 柠檬 / 桃，左手 D/F、右手 J/K。
5. 被试信息登记与实验1 完全一致：启动弹 Qt 对话框（姓名、编号、年龄、性别、漂移方向），
   编号留空自动生成，方向选“自动”按编号末位奇偶分配，随后有全屏确认页（`R` 重填）。

## 4. 单区段流程（与 2.2 一一对应）

```
注视点 +(1000 / 1500 / 2000 ms，随机)
        ↓
作答窗口打开（2 / 3 / 4 s，随机，窗口内可做任意多题）
        ├─ 图片 + 叠加词 → 按键 → 空屏 150 ms → 下一题
        ├─ 图片 + 叠加词 → 按键 → 空屏 150 ms → 下一题
        └─ …直到窗口剩余时间不足 0.35 s（或某一题超时没作答）
        ↓
反馈 1500 ms：  本次得多少分（+0 / +10 / +20 …）
                分数是否取决于表现（键帽 = 看表现 / 骰子 = 随机）
```

几个实现细节：

- **窗口内没有“单题超时”**：图片一直显示到被试按键。只有在窗口恰好用完的那一题会记为
  未作答（`反应键` 为空），此时该区段立即结束。
- **一题结束到下一题之间插 150 ms 空屏**（`ISI_BETWEEN`），避免一次连击被算到两道题上。
- **主任务里不给逐题正误反馈**：被试只从区段得分和图标推断表现，这与原文“从反馈中估计
  效能”的设计一致；练习阶段才给逐题正误。
- 一致 / 不一致按 `COND_RATIO = 0.5` 逐题抽取：一致 = 词与图相同，不一致 = 词是另一种水果。

## 5. 参数对照表（改实验就改 `CFG`）

| 参数 | 含义 | 默认 |
|---|---|---|
| `N_INTERVALS` | 正式区段数 | 288 |
| `FIX_CHOICES` | 注视点时长候选 | (1.0, 1.5, 2.0) |
| `WINDOW_CHOICES` | 作答窗口候选 | (2.0, 3.0, 4.0) |
| `FB_DUR` | 区段反馈时长 | 1.5 s |
| `MIN_TRIAL_TIME` | 窗口剩余不足此值就不再开新题 | 0.35 s |
| `ISI_BETWEEN` | 同区段两题之间空屏 | 0.15 s |
| `POINT_PER_CORRECT` | 答对一题得分 | 10 |
| `YOKE_WINDOW` | yoking 窗口长度（表现区段个数） | 10 |
| `YOKE_INIT_SCORES` | 初始窗口分数 | 8×30 + 2×10 |
| `P_MIN` / `P_MAX` | 效能概率范围 | 0.10 / 0.90 |
| `TRAJ_SEED` | 漂移轨迹种子 | 20260202 |
| `TRAJ_SMOOTH` | 漂移平滑度（越大越慢） | 0.05 |
| `PROBE_EVERY` | 探针间隔（区段数） | (2, 4) |
| `COND_RATIO` | 一致题比例 | 0.50 |
| `PIC_SIZE` / `WORD_HEIGHT` | 图片边长 / 词字号（占屏高） | 0.50 / 0.080 |
| `FRUIT_FILL_GRAY` / `FRUIT_LINE_GRAY` | 水果填充 / 描边灰度（0–255） | 78 / 158 |
| `SHOW_EFF_LABEL` | 图标下是否写一行说明 | True |
| `BREAK_EVERY` | 每多少区段休息（0 = 不休息） | 48 |

> 颜色仍然遵循“PsychoPy 的 rgb 是 −1…1”的规矩：脚本里用 `rgb255()` 按 0–255 填，
> 水果图用 0–255 灰度值（它们只进 Pillow，不进 PsychoPy）。

## 6. 四个核心机制怎么实现的

**① 效能漂移（2.2）** `make_trajectory()`
高斯白噪声 → 环形高斯核平滑 → 映射到 [0.1, 0.9]，种子固定 `TRAJ_SEED = 20260202`。
`reverse=True` 得到镜像序列，被试在对话框选“正向/反向”（或按编号奇偶自动分配），
用来平衡时间顺序效应。轨迹按 **288 个区段**生成，与实验1同参数但不同种子。

**② 连续分数的 yoking（2.2）** `YokeWindow`
窗口存最近 10 个**表现区段的得分**（不是 0/1）。随机区段的分数直接从窗口里抽一条，
于是两类区段的得分分布被强制匹配；每来一个表现区段，它的得分入窗、最旧的一条出窗。
初始窗口 `8×30 + 2×10`（均值 26），约 10 个表现区段后初始值被完全替换。

选择“从窗口里抽”而不是“抽均值 + 噪声”的原因：前者保证抽到的分数一定落在真实出现过的
取值范围内，不会造出被试从没见过的分数（比如 10 分和 40 分之间凭空出现 27 分）。

**③ 自由作答窗口** `run_interval()`
窗口开始记时（`int_clock`），循环“出题 → 等键 → 空屏”，直到
`窗口剩余 < MIN_TRIAL_TIME`。`event.waitKeys(maxWait=剩余时间)` 保证按键不会跨窗，
窗口用完立刻进反馈。

**④ 主观探针（2.2）** `make_probe_schedule()` + `run_probe()`
每 2–4 个区段插一次，效能探针与奖赏探针交替（288 区段约 90 个，各半），
0–100 VAS，必须拖动过滑块才能按空格确认（防一路空格）。鼠标接口做了跨版本兼容，
并留了 `←/→` 键盘兜底。

**⑤ 窗口长度的平衡** `make_score_schedule()`
原文写“随机取 2000/3000/4000 ms”。这里改成 **三个长度各 1/3 再整体打乱**：纯随机在
288 段上会出现某长度偏多，进而让“每段平均题数”抖动，而它是要进模型当协变量的。
想恢复纯随机，把 `run_main` 里 `windows` 换成
`[self.rng.choice(CFG["WINDOW_CHOICES"]) for _ in range(n)]` 即可。

## 7. 数据输出

`data/<编号>_<姓名>_<时间戳>/` 下四个文件：

**`trials.csv`**（每答一题一行，DDM 用这个）

```
被试 组别 阶段 区段 区段内序号 窗口s 区段内开始时刻s 条件 图片 图片代号 词
正确键 反应键 正确 反应时 过快
```

- `过快` = RT < 250 ms（原文 2.3 要求剔除），已提前标好，分析时 `filter(过快==0)` 即可。
- `区段内开始时刻s` 是这道题在窗口内的开始时间，可用于检查“越往后越急躁”之类的漂移。

**`intervals.csv`**（每区段一行，学习模型用这个）

```
被试 组别 阶段 区段 窗口s 实际用时s 试次数 正确数 正确率 一致比例
效能概率 效能类型 得分来源 区段得分 累计得分
```

- `效能概率` 是这一段的 p（看表现的概率），`效能类型` 是这一次抽样结果（performance/random）。
  学习模型要拟合的就是 `效能类型` 序列，`效能概率` 只用于核对轨迹。
- `得分来源`：`表现`（真实得分）/`抽取`（yoking 抽到的）/`练习`。
- `一致比例` 就是 2.3 里“区段内平均一致性水平”那个控制变量。

**`probes.csv`**：探针类型、插入位置（第几个区段之后）、评价值（0–100）、用时。

**`meta.json`**：姓名、编号、年龄、性别、方向、区段数、总分、平均每区段得分/题数、
yoking 窗口末态均值、轨迹种子、版本号。

## 8. 接到分析上（2.3）

- **DDM**：用 `trials.csv`，`正确` 作反应、`反应时/1000` 作 RT，剔除 `过快==1`；
  按 `区段` 合并 `intervals.csv` 的 `效能概率`（或模型衍生的效能估计）与探针估计，
  进入漂移率与阈限方程；一致性（`条件`）只进漂移率；区段长度用 `窗口s`。
- **学习模型**：`intervals.csv` 的 `效能类型` 序列 → 0/1 反馈序列；
  `区段得分` 序列 → 奖赏量序列（实验2 学的是**量**不是概率）。
  单学习率 / 双学习率 / 截距三个模型与实验1 完全一致，可直接套同一份 mfit 代码。
- **探针**：`probes.csv` 的 `评价值/100` 就是模型的观测值；`插入位置` 对齐到 `区段`。

## 9. 换成自己的水果图

`stimuli/fruit_apple.png` 等四张图可以直接替换：

- 透明底 PNG（RGBA），正方形，建议 ≥ 512×512
- 主体居中，四周留约 10% 空白
- 灰度或彩色都行；程序按 `PIC_SIZE` 等比缩放，不会拉伸变形
- 文件名必须是 `fruit_apple.png` / `fruit_pear.png` / `fruit_lemon.png` / `fruit_peach.png`

删掉 `stimuli/` 整个文件夹，下次运行会按内置几何重新生成默认图。
想彻底不用自动生成（例如换成真实照片），把四张图放好即可——程序只在缺图时才画。

## 10. 常改需求

| 想做的事 | 改法 |
|---|---|
| 区段太少/太多 | `N_INTERVALS` |
| 窗口更长（每题更多） | `WINDOW_CHOICES`，如 `(3.0, 4.0, 5.0)` |
| 每题分值改成 5 分 | `POINT_PER_CORRECT = 5` |
| 只跑一致条件（做对照） | `COND_RATIO = 1.0` |
| 加中性词条件（非水果词） | `make_trial_content()` 里加一支，词从 `["桌","窗","门"]` 抽 |
| 探针少一点 | `PROBE_EVERY = (4, 6)`（约 58 个） |
| 不想显示累计分数 | `SHOW_TOTAL_SCORE = False` |
| 反馈里不写文字、只留图标 | `SHOW_EFF_LABEL = False`（更接近实验1 的纯图标版） |
| 换成自己的按键 | `KEYS` 改键位，注意要四个不同的键 |
| 想中途看数据 | 每 10 个区段自动落盘一次，`data/` 里随时可看 |

## 11. 常见坑

- **`ModuleNotFoundError: PIL`**：用了系统 python。改 PsychoPy 自带的 python（图形界面 Run 就行）。
- **中文变方块**：系统没 `Microsoft YaHei`，改 `CFG["FONT"]`。
- **水果图是黑块/纯白块**：图片被替换成了非 RGBA 或全透明，删掉 `stimuli/` 让它重新生成。
- **窗口内只做了 1 题就结束**：检查 `MIN_TRIAL_TIME` 是否被调大，或键盘是否连击被吞。
- **`Mouse` 没有 `getPressed`**：PsychoPy 2024.x 删了这个方法，脚本已用 `mouse_left_pressed()`
  兼容，并用 `←/→` 兜底；若探针拖不动，先用方向键确认能作答。
- **按 ESC 中途退出**：会先落盘再退出，数据不会白跑；异常崩溃时还会写 `error.log`。
- **正式采集前清空 `data/`**：快跑和正式数据混在一起容易撞被试号。
